# DOCKER_SYNOLOGY.md

## Перед сборкой
Уточнить модель NAS, CPU architecture, DSM/Container Manager, RAM, свободный диск, доступность аппаратного ускорения, firewall и исходящие peer-соединения.

## Образ
- multi-stage build Rust + frontend.
- фиксированные версии base images и зависимостей.
- FFmpeg с проверенными muxer/demuxer/codecs.
- непривилегированный пользователь, если возможно.
- не использовать `latest` в production.
- не монтировать Docker socket.
- не включать `privileged: true` без документированной необходимости.
- корректная обработка SIGTERM.

## Volumes и сеть
- `/cache` — ограниченный временный cache.
- `/config` — опциональная конфигурация.
- постоянная БД в MVP не нужна.
- публиковать только web/API port.
- не открывать peer ports без явного решения.
- для удалённого доступа рекомендовать VPN или защищённый reverse proxy с TLS/auth, а не открытый API.

## Конфигурация окружения

Приложение должно поддерживать следующие настройки или документированные эквиваленты:

| Настройка | Назначение |
|---|---|
| `APP_HOST` | HTTP bind address |
| `APP_PORT` | HTTP port |
| `RUST_LOG` | Уровень логирования |
| `HWACCEL_MODE` | `auto`, `vaapi` или `software` |
| `VAAPI_DEVICE` | Настроенный DRM render node |
| `HWACCEL_REQUIRED` | Является ли отказ требуемого аппаратного ускорения фатальным |
| `FFMPEG_PATH` | Путь к FFmpeg executable |
| `FFPROBE_PATH` | Путь к FFprobe executable |
| `CACHE_DIR` | Временный media и HLS cache |
| `SESSION_DIR` | Состояние playback-сессии и артефакты |

Сервис должен валидировать конфигурацию при запуске и понятно сообщать о недопустимых значениях.

Не выводить секреты при логировании конфигурации. Environment variables, содержащие credentials или API tokens, должны быть redacted.

## Требования к образу FFmpeg

Образ приложения должен содержать:

- Скомпилированный Rust backend.
- FFmpeg.
- FFprobe.
- Возможности сборки FFmpeg, необходимые для HLS output.
- Поддержку VA-API в FFmpeg для образа с аппаратным ускорением.
- Совместимые userspace-библиотеки драйвера VA-API для целевого окружения.
- Опциональный `vainfo` для диагностики, если упакован.
- Любые нативные зависимости, требуемые выбранным source engine.

Фиксировать версии base image и зависимостей в воспроизводимых сборках. Не зависеть от неверсионированного состояния package repository в production-релизах.

Процесс сборки должен проверять возможности, например:

```
ffmpeg -version
ffmpeg -hwaccels
ffmpeg -encoders
ffmpeg -filters
ffprobe -version
```

Само наличие `vaapi` в `ffmpeg -hwaccels` не доказывает, что GPU можно инициализировать. Приложение также должно выполнять проверку устройства в runtime и, где необходимо, репрезентативный encode-тест.

Итоговый образ должен сообщать свою архитектуру и возможности сборки FFmpeg через диагностическую команду или документированный health endpoint.

## Политика аппаратного ускорения

`HWACCEL_MODE=auto`

- Определить, существует ли пригодное устройство VA-API.
- Проверить, доступны ли требуемые компоненты FFmpeg.
- Протестировать операцию, требуемую выбранным playback plan.
- Использовать VA-API, когда операция успешна.
- Перейти на software, когда это разрешено.
- Зафиксировать выбранный режим и краткую причину отказа.

`HWACCEL_MODE=vaapi`

- Попытаться использовать VA-API.
- Если аппаратное ускорение недоступно, применить политику `HWACCEL_REQUIRED`.
- Не заявлять молча, что аппаратное ускорение использовалось, если это не так.

`HWACCEL_MODE=software`

- Не требовать GPU-устройство.
- Не инициализировать VA-API.
- Использовать поддерживаемые software paths.

`HWACCEL_REQUIRED=true`

Когда операция playback требует аппаратного ускорения, а требуемый аппаратный путь недоступен, завершать операцию с понятной диагностикой вместо незаметного перехода на software.

Сервис должен по-прежнему запускаться, если продуктовый дизайн допускает работу без аппаратного ускорения playback; задокументировать, влияет ли strict mode (`HWACCEL_REQUIRED=true`) на запуск, создание playback или только на операции, требующие GPU.

## Health checks и диагностика

Сервис должен различать базовое здоровье процесса и аппаратные возможности.

Рекомендуемая диагностическая информация:

- Версия приложения.
- CPU architecture.
- Версия FFmpeg.
- Поддержка VA-API в сборке FFmpeg.
- Настроенное устройство VA-API.
- Существование устройства и права доступа.
- Результат инициализации VA-API.
- Имена доступных энкодеров, релевантные сборке.
- Результат последнего репрезентативного hardware-теста.
- Использует ли текущая playback-сессия stream copy, VA-API или software transcoding.

Не раскрывать необработанные host paths, credentials или подробную системную информацию неаутентифицированным пользователям.

Отсутствие GPU не обязательно делает всё приложение нездоровым. Сервис может быть здоровым в software mode, сообщая при этом, что аппаратное ускорение недоступно.
