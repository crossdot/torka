# ADR-007: Каталог метаданных (external metadata)

- Status: Proposed
- Date: 2026-10-29
- Owners: ведущий инженер (Discovery)

## Context

DECISIONS.md оставляет открытым вопрос: нужен ли внешний каталог метаданных (постеры,
описания, рейтинги) в MVP. `ENV.example` уже содержит неиспользуемый `METADATA_API_KEY=`
(пустой).

## Options

1. **Без внешнего каталога в MVP.** Показывать только метаданные провайдера (title/year/
   size/quality/languages) + технические данные из FFprobe; неизвестное = null.
2. Интеграция каталога (TMDB/IMDb/…) — добавляет ключи, лицензию/ToS внешнего API,
   сетевые вызовы, кеш.

## Decision

**Вариант 1.** Внешний каталог метаданных исключён из MVP. `METADATA_API_KEY` остаётся
неиспользуемым/опциональным; при необходимости вернуться отдельным ADR. FFprobe
предоставляет только технические метаданные (длительность, потоки, кодеки) в рамках сессии.

## Consequences

- Меньше зависимостей, ключей и сетевых рисков; соответствует PRODUCT.md («не выдумывать
  неизвестные метаданные»).
- UI показывает «сырые» метаданные провайдера; без постеров/описаний.

## Validation

- Согласуется с PRODUCT.md (не-цели: профили/история; принцип «не выдумывать метаданные»).
